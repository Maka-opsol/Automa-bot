# Narrow CI checks — not staged-patch validation

This review branch adds only a `pull_request` workflow and standard-library-only, mocked tests. The production `test-validation-suite.js` is identical to the branch's main baseline: the earlier review-branch change that unconditionally blocked staged paths has been removed to avoid breaking ordinary self-heal promotions. **This is not a security fix for the existing promotion gate.** No PR, branch protection, production deployment, or live validation is created by this branch.

## What the green CI check means

The workflow checks tracked JavaScript with `node --check`, and tests the current validator's `auth_flow` and `database_integrity` behavior with fake browser, auth, database, logging, filesystem and process dependencies. There are positive and negative cases for the URL, authentication exception, integrity failure and absent dependencies; they also check browser cleanup and cwd restoration. A characterization test demonstrates that changing a fake cwd still uses the same injected dependencies: **it does not validate staged code**. The tests don't invoke the real sandbox, CLI, TypeScript modules, bot, browser, database, network or production services. Each test command has a 40-second limit. Node 20+ is required, but the hosted runner image and Node are not version-pinned.

The workflow uses `pull_request`, not `pull_request_target`, and the full-SHA pinned checkout has `persist-credentials: false`. Only `contents: read` is granted; no secrets, environments, npm install, artifacts, bot credentials, or production job are configured. PR code nevertheless executes on a networked hosted runner and PR changes to the workflow or tests could weaken checks. Have trusted reviewers review workflow and test changes and use suitable branch protections or organization-controlled required workflows. Direct dashboard or other writes to main bypass PR checks unless separately prevented. A green result is not proof of patch safety, isolation, integration health, a TypeScript build/typecheck, or promotion-gate security.

## Existing unresolved production gaps

* `validateBeforePromotion(stagingSource)` changes cwd, but that does not redirect already loaded imports or injected dependencies to the staging tree. A passing result is not evidence the staged patch was tested. The existing `results.every(...)` is also vacuously true for an empty result list. This branch deliberately leaves the production function unchanged, so the baseline's unsafe behavior remains.
* `self-heal.ts` substitutes the truthy `{ passed: true }` when the validator cannot be loaded. `ACCEPT_ANY_FIX` and `EXECUTIVE_MODE` explicitly skip pre-promotion validation, and also bypass other checks. These gaps remain; the workflow is not a substitute for fixing them.
* The baseline sandbox self-test passes `module.exports = { test: true };` and `/tmp/test.js`. The sandbox blocks newly introduced `module.exports` and checks that a target is inside the project; this is not a valid positive test for the actual sandbox. It also tests `result !== false`, so a rejected `{ safe: false }` object can be misreported as a pass. The new mocked critical-check tests do not exercise or fix this bug and must not be described as real sandbox tests. A proper repair needs a valid project-contained target, valid non-prohibited patch and positive and negative cases against the real executor with its effects contained.
* `npm run validate` uses plain `node test-validation-suite.js`; the baseline module merely exports functions rather than invoking the suite, and Node lacks a configured TypeScript loader there. With missing runtime dependencies it may fail to load, and a zero exit on successful import is not evidence tests ran. This branch does not change the command, install dependencies, or run it against production resources.

Before claiming fail-closed promotion security, design and test genuinely isolated validation of the staged tree, close missing-validator and opt-in bypass paths according to an approved policy, correct the real sandbox self-test and CLI, and check compatibility with ordinary self-heal. Keep credentials and production execution out of untrusted CI. The existing broad dependency versions, missing lockfile and placeholder `lint` are also unchanged.
