# NON-DEPLOYABLE — Dashboard Actions Ollama auditor review candidate

**Local review candidate only: do not merge, deploy, dispatch, enable writes, or treat this as a completed integration.** The candidate replaces `.github/workflows/dashboard-auditor.yml` in the local tree based on bot main `1b0955d70e559de2df705a2a5b9170da6e7bccaa`. Its first step is an unconditional hard stop: every run fails before checkout and no artifact is produced. Removing that stop requires independent review and resolution of the blockers below. The inherited file in `review-only/` is not the active candidate.

## Purpose and limits

This workflow is an advisory, not a security proof and not an auto-committer. It only inspects existing single-file replacement patches; it never runs candidate or baseline code. It checks the exact baseline git blob at the exact path in the dispatched commit, canonical candidate bytes, and a locally computed unified diff, and supplies all three to each review. Three distinct, sequential perspectives use the **same** small model; they are correlated, not independent models. Inference cannot guarantee malicious changes or prompt injection will be caught. Keep deterministic restrictions, sandboxing, user-defined safeguards, and compare-and-swap at commit time; do not treat an LLM verdict as sole authorization. No self-modification of `auditor/` or `.github/` is authorized by this evaluator.

Strict UTF-8 source (no normalization), 4096 bytes per source, bounded diff/context, and the conservative privacy denylist deliberately reject many legitimate files and patches, including files containing URLs or email addresses. Control and invisible formatting characters, Unicode line separators and the model special-token delimiter `<|` are rejected. `README.md` is also limited to 4096 bytes here; it must retain the baseline byte-for-byte and append at most 1024 bytes and 20 lines of ASCII letters, numbers, spaces, comma, period, question mark, exclamation mark, hyphen or newline, including at least one letter or number. The baseline must end in newline. Large files need a separately designed authenticated, private transfer and bounded complete-context review; never silently truncate. GitHub's 65,535-character *total* workflow_dispatch inputs ceiling is not a safe size for base64 file transfer without a smaller local cap. Reject at the dashboard before dispatch. The denylist is not a secret scanner and does not prove there are no credentials or personal/academic data.

## Exact protocol and migration

The four workflow inputs stay `nonce`, `path`, `base_blob`, `candidate_b64`. The candidate is a canonical base64 encoding of nonempty, strictly valid UTF-8 bytes; hashes bind the exact original bytes without Unicode normalization. `base_blob` is the lowercase Git SHA-1 blob for that exact path at workflow `github.sha`, not the commit SHA. No path traversal, symlinks, submodules, missing paths, or blob substitution is allowed. Only `js`, `mjs`, `cjs`, `ts`, `tsx`, `jsx` and `README.md` are accepted, and only ordinary Git files. Identical candidates are rejected. Invalid input or a failed setup creates no artifact and fails the run. A model failure/invalid vote yields a completed run with `safe:false` and incomplete votes; the consumer must reject it.

Artifact `audit-<nonce>` contains exactly `dashboard-audit-verdict.json`. It is **version 2**, with exact top-level keys: `version`, `job`, `nonce`, `path`, `base_blob`, `candidate_sha256`, `workflow_sha`, `run_id`, `run_attempt`, `baseline_verified`, `safe`, `votes`. `run_id` is a decimal string; `run_attempt` is integer 1. The three exact vote objects are `{"provider":"ollama#security","is_safe":true}`, `{"provider":"ollama#correctness","is_safe":true}`, `{"provider":"ollama#intent","is_safe":true}`. Require all and reject unknown, missing, duplicate, malformed or false votes. The client must independently compute candidate SHA-256, verify nonce/path/base/candidate/run/attempt/workflow SHA/job, validate `baseline_verified === true`, strict JSON and exact keys, and require `safe === true`.

The v2 consumer must reject v1 and require all explicit votes and bindings. Dashboard admission must reject both baseline and candidate above this evaluator's 4096-byte limit, including README, before dispatch; no truncation. The separately inspected local dashboard review candidate allows up to 16000 bytes for README, so that mismatch remains. Its character policy may also be stricter than the evaluator. No integrated live system was tested here. Consumer must verify repository, workflow ID/path, trusted workflow commit, dispatched run ID, actor/triggering actor, run attempt, successful job/run, artifact identity/repository/head SHA, single safe archive member and size; reject reruns/replays. Store a cryptographic nonce journal atomically. Recheck the main branch and base blob immediately before a compare-and-swap commit. A verdict does not authorize merging a different revision or candidate.

## Sandbox blocker

A separately reviewed, isolated, bounded, secret-free, no-network execution canary and teardown for untrusted candidate code have not been established and adversarially verified. This evaluator does not execute candidates and is not a replacement for such a canary. No existing dashboard sandbox is proven safe here; do not run candidate code in the dashboard process or bypass the fail-closed canary. Durable replay/write journals, atomic compare-and-swap and independent end-to-end security review remain unverified. This branch does not restore autonomous source patching.

## Predeployment controls

1. Independently review the evaluator, this workflow candidate, runtime archive SHA-256 and model manifest digest. The active-path candidate pins evaluator commit `1b0955d70e559de2df705a2a5b9170da6e7bccaa` and checks evaluator Git blob `c9eb4e5cbb6cff9c8608860c4311c4341e1f1643`, not the dispatched branch. Retain the commit in repository history. Whenever changing auditor code, create and review a code commit first, then update the workflow pin in a separate commit. Protect workflow and evaluator code with branch rules and trusted reviewers; restrict workflow dispatch/rerun and branch write privileges to trusted identities. Workflow identity and artifact origin checks in the dashboard are mandatory: an attacker able to replace the workflow can mint fake verdicts.
2. The proposed template is designed to run only on `refs/heads/main`, attempt 1, repository `Maka-opsol/Automa-bot`. A remote test branch must use a separately reviewed temporary branch/ref allowlist change AND a dashboard test verifier configured to trust only that exact workflow/commit. `workflow_dispatch` must exist on the default branch before GitHub accepts dispatches to any branch. Do not loosen production checks to test.
3. Runner is a fresh GitHub-hosted `ubuntu-24.04`; `contents: read`, no explicit repository/environment secrets, no persisted checkout credentials, no candidate execution. Pinned checkout/upload actions, Ollama 0.13.5 release archive checksum, API version and Qwen model manifest digest are checked. The Qwen tokenizer JSON and tokenizers 0.22.2 wheel are pinned by SHA-256 and the evaluator rechecks the tokenizer JSON and package version. The reviewed runtime and tokenizer are part of the trusted computing base. Runner image/Python are not immutable. The server runs loopback with cloud disabled; no model tools are provided. Restrict runner/network access and GitHub Actions visibility as appropriate. This is not an OS isolation boundary against a compromised runtime/action/runner. Model assets and runtime are downloaded over the network.
4. **Privacy:** workflow dispatch inputs, run metadata and source may be visible to people with Actions access, and may have GitHub retention/logging beyond artifact expiry. Never send credentials, student data or private material to a public repository or public Actions logs. Base64 is not encryption. Only a hash and short votes appear in the artifact; no source or model reasons are intentionally logged. Restrict read access to the repository and Actions, apply dashboard admission controls and secret/data scanning, and inspect actual retention policies. This workflow alone cannot guarantee privacy.
5. Complete-context gate: the auditor constructs its own raw ChatML prompt, forbids special-token delimiters in data, counts it with the pinned Qwen tokenizer, reserves 512 output tokens in a 32768-token context, explicitly disables truncation and context shifting, and requires Ollama prompt_eval_count to equal the exact count. A mismatch fails closed. This verifies consistency with a trusted runtime, not that an adversarial server or model actually attended to the source. The tokenizer-to-GGUF equivalence and raw-mode count must be checked against the pinned real runtime before any rollout.
6. Resolve the timing mismatch before any rollout: the dashboard verifier defaults to 240 seconds and caps at 300 seconds, while this job allows 30 minutes and three sequential inference requests can each take 240 seconds, plus queue, setup, downloads and artifact delivery. No real timing was measured, and increasing a timeout without evidence is not a solution. A separately designed durable authenticated asynchronous pending decision, with nonce/run/base/candidate/workflow identity, one-use replay protection, expiry, cancellation, recovery and atomic commit-time CAS, is a possible direction but is not implemented here. Missing, late, timed-out, failed or incomplete results must remain rejection. This candidate has only mocked Ollama tests; no live GitHub Action, real Ollama inference, action supply-chain audit or production integration was performed. Revalidate pinned upstream model tags, checksums, and action commits before release; do not bypass mismatches.

## Offline test

Install the hash-pinned tokenizer wheel without dependencies and download the hash-pinned tokenizer JSON as shown in the workflow. Set `TOKENIZER_PATH` to that JSON and from repository root run `python3 -m unittest discover -s auditor -p 'test_*.py' -v`. A local HTTP server impersonates the Ollama API only in tests; the production client has a hard-coded loopback endpoint, verifies the model digest, and does not use proxies or follow redirects. The test creates a throwaway Git repository and runs the same entry point as the workflow. No production files or candidate source are executed.
